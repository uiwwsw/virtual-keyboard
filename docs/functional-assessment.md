# 개선 내역과 검증 범위

## 입력 동작

- 운영체제에 관계없이 한글 모드와 Shift를 동일하게 해석합니다. F1, Dead, Process 같은 특수키가 텍스트로 삽입되지 않습니다.
- 조합 중 Backspace는 자모 단위, 조합 완료 후에는 글자 단위로 동작합니다.
- 커서 이동과 삭제가 이모지·결합 문자 경계를 지킵니다. 선택 방향에 맞게 범위를 접고, 입력 시 선택 영역을 교체합니다.
- 제어 값의 초기화·거절·길이 변경에 맞춰 표시 값과 커서를 유지합니다.
- 입력란별 정책이 Provider의 언어 선호도를 덮어쓰지 않습니다. 활성 입력란의 모드 변경도 즉시 키패드에 반영합니다.
- 사용자 키의 label/value를 분리하고 선택적 label/type 및 여러 글자 매크로를 지원합니다.
- 기본 alphanumeric 레이아웃에 숫자 행을 제공합니다.
- disabled, readOnly, maxLength, onValueChange, 클립보드 실패 알림과 소비자 이벤트 핸들러를 지원합니다.

## 렌더링과 접근성

Canvas와 상시 requestAnimationFrame 루프를 제거했습니다. 입력 텍스트는 DOM의 문자 요소로, 키는 Shadow DOM 내부의 실제 button으로 렌더링합니다. 키보드의 크기 변화는 ResizeObserver로 측정하며 기존 body padding을 덮어쓰지 않습니다. 전역 focus 이벤트, 반복 입력 타이머, 드래그·길게 누르기, 스토리지와 뷰포트 리스너는 종료 시 정리합니다.

키패드는 데스크톱에서도 표시할 수 있고, 테마·닫기·포커스 표시·safe area를 지원합니다. SSR에서는 window/navigator 없이 패키지를 가져오고 초기 HTML을 렌더링할 수 있습니다.

실행 취소·다시 실행은 입력란별로 격리하며 외부 제어 값 초기화 시 이전 기록을 버립니다. 숫자·기호 자판과 전체 선택을 추가했습니다. 공개 ref API로 포커스·선택·값 조회·편집을 제어할 수 있습니다.

## 데모와 개발 환경

7개 모드, 모드별 값 보존, 실시간 출력, 코드 예제, 초기화·예시 채우기, 라이트·다크 테마, 설치 명령어 복사를 제공하는 반응형 데모로 정리했습니다. 페이지 제목, 한국어 문서 언어, 설명, favicon도 프로젝트에 맞췄습니다.

실제로 JavaScript를 번들하는 라이브러리 빌드와 데모 빌드를 분리했습니다. 타입 export 순서, React peer dependency, 자동 prepack을 정리했으며 npm lockfile을 단일 기준으로 사용합니다. 검증을 거쳐 보안 수정 버전으로 의존성을 업데이트했습니다.

실제 npm tarball을 생성·압축 해제하여 서버에서 import하며 NodeNext 소비자 프로젝트의 타입 검사를 실행합니다. 브라우저 테스트는 개발 서버 대신 배포용 빌드로 실행합니다. npm registry 확인 실패는 게시를 중단하며 명시적인 E404일 때만 미게시 버전으로 취급합니다.

CI와 기존 publish 워크플로에 포맷·린트·회귀 테스트·빌드·패키지 검사와 브라우저 검증을 연결했습니다.

## 검증 명령

```bash
npm run check
npm run test:e2e
npm audit
```

컴포넌트 테스트는 StrictMode, 빠른 연속 입력, 제어 값, 정책 전환, 커스텀 키, 클립보드 실패, 다중 Provider를 검사합니다. 편집 엔진 테스트는 한글 조합, 자모 삭제, 선택 교체, 이모지, 길이 제한을 검사합니다.

Playwright는 데스크톱·Pixel 뷰포트의 Chromium과 iPhone 뷰포트의 WebKit에서 한글 타이핑, 삭제·선택, 모드·테마, 커스텀 키, 초기화, 물리 키보드, 키패드의 키보드 접근, 실제 터치 탭, 작은 화면의 넘침·가림을 검사합니다. 빠른 연속 터치와 키 사이·툴바 여백의 포커스 유지, 언어 전환을 검사하며 모바일 Chromium에서는 두 손가락의 겹치는 터치도 검증합니다. axe는 두 테마의 WCAG A/AA 자동 검사를 실행합니다.

제스처 회귀 검사는 터치 취소·스크롤·드래그 복귀·길게 누르기 단어 선택·반복 삭제 중단과 가로 화면의 키 높이·가림을 확인합니다. 모바일 Chromium에서는 브라우저의 실제 터치 프로토콜로 페이지 스크롤과 겹치는 두 손가락 입력도 확인합니다. 버튼 실행은 손을 떼는 시점으로 통일하고 스크롤 중에는 커서·선택을 유지합니다.

## 검증의 한계

- 모바일 WebKit 에뮬레이션은 실제 iPhone Safari 테스트와 같지 않습니다. 실제 기기의 확대·화면 회전·브라우저 툴바·클립보드 권한은 출시 전 확인해야 합니다.
- 자동 접근성 검사로 스크린 리더의 전체 입력 경험을 보증하지 않습니다. VoiceOver와 TalkBack에서 별도로 확인해야 합니다.
- 실제 HTML input의 자동완성, 폼 제출, 운영체제 IME·음성 입력는 지원하지 않습니다.
- 기존 custom element/Canvas 내부 구조를 대상으로 작성한 CSS는 입력란의 className/style 기반으로 옮겨야 합니다.
- 프로젝트가 변경된 출력 경로를 사용하므로 기존 호스팅 설정은 demo-dist로 변경해야 합니다.

main 반영 뒤 연결된 Vercel 배포와 npm 게시 워크플로를 확인합니다. 실기기·보조기기 검증은 위 범위와 별도로 수행해야 합니다.
